Set up a webhook

pici starts workflows when your Git provider sends a webhook. The webhook secret is optional but recommended: it lets pici check that deliveries really come from your provider.

{{if eq (printf "%s" .Provider) "github"}}

GitHub {{if .WebhookSetupURL}}· Open webhook settings{{end}}

  1. Payload URL: {{template "webhook_payload_url" .WebhookPayloadURL}}
  2. Content type: application/json
  3. Secret: the value in the Webhook secret field.
  4. Which events? choose Let me select individual events, then tick Pushes and Pull requests.
  5. Keep Active checked and click Add webhook. GitHub sends a ping event that pici acknowledges.
{{if not .WebhookSetupURL}}

Fill in the Repository URL above to get a direct link to the webhook settings.

{{end}} {{else if eq (printf "%s" .Provider) "gitlab"}}

GitLab {{if .WebhookSetupURL}}· Open webhook settings{{end}}

  1. URL: {{template "webhook_payload_url" .WebhookPayloadURL}}
  2. Secret token: the value in the Webhook secret field. Use Secret token, not Signing token: pici verifies the X-Gitlab-Token header.
  3. Trigger: tick Push events, Tag push events and Merge request events.
  4. Keep Enable SSL verification checked and click Add webhook.
{{if not .WebhookSetupURL}}

Fill in the Repository URL above to get a direct link to the webhook settings.

{{end}} {{else}}
Webhooks are only supported for GitHub and GitLab projects. Set the provider above to get setup instructions.
